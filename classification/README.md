## 🚀 วิธีใช้งาน 4 ขั้น (สำหรับข้อมูลใหม่ของคุณ)

### ขั้นที่ 1 — วางไฟล์ข้อมูล

วางไฟล์ CSV ไว้ในโฟลเดอร์นี้:

```
C:\Users\computer\Documents\ML_test\classification\my_data.csv
```

**เงื่อนไข target**: คอลัมน์ที่ทำนายต้องมี **2 คลาสขึ้นไป** (yes/no, หมวดสินค้า, กลุ่มลูกค้า)

### ขั้นที่ 2 — แก้ใน `my_run.py` (บล็อก `# ==== แก้ตรงนี้ ====` หัวไฟล์)

```python
# ===================== แก้ตรงนี้ =====================
CSV_PATH = "data.csv"        # ← ชื่อไฟล์ข้อมูลของคุณ
TARGET = "default"           # ← ชื่อคอลัมน์ที่ต้องการทำนาย (yes/no หรือหมวด)
DROP_COLS = ["app_id"]       # ← คอลัมน์ ID/ชื่อ/วันที่ ที่ไม่ควรใช้ (สำคัญ! ถ้าไม่ตัด ID จะเป็น feature ปลอม)

# ถ้าส่งอาจารย์แค่บางโมเดล ให้ใส่เฉพาะชื่อที่มี เช่น MODELS = ["knn"]
MODELS = ["logistic", "knn", "tree", "nb", "svm", "rf", "gb", "ada", "mlp", "lda"]
# ====================================================
```

| ตัวแปร | ความหมาย | ค่าที่ใส่ได้ |
|---|---|---|
| `CSV_PATH` | ชื่อไฟล์ CSV | `"my_data.csv"` |
| `TARGET` | คอลัมน์คำตอบ (2 คลาสขึ้นไป) | `"default"`, `"approved"`, `"grade"` |
| `DROP_COLS` | คอลัมน์ที่ห้ามใช้เป็น feature (ID/ชื่อ/วันที่/เลขแถว) | `["app_id"]`, `["customer_id", "sold_date"]` |
| `MODELS` | โมเดลที่จะรัน (โค้ดข้ามไปถ้าไฟล์หาย) | `logistic, knn, tree, nb, svm, rf, gb, ada, mlp, lda` |

> ⚠️ **อย่าลืม `DROP_COLS`**: คอลัมน์ ID เลขที่วิ่ง 1,2,3,... ถ้าปล่อยเข้าโมเดล = ใส่ "เสียงรบกวนปลอม" และโมเดลบางตัวอาจให้ความสำคัญมันผิด ๆ

### ขั้นที่ 3 — รัน

### ขั้นที่ 4 — อ่านผล

```
rows 774/800 | features 9 | target default | classes 2 | outliers 11

Model                                 Accuracy   Precision      Recall          F1
----------------------------------------------------------------------------------
Logistic Regression                     0.6968      0.4531      0.7073      0.5524
...
baseline (ทำนายคลาสที่บ่อยสุด): 0.7355
```

**วิธีอ่านให้ถูก:**

| ตัวชี้วัด | ความหมาย | ระวัง |
|---|---|---|
| `Accuracy` | ทายถูกกี่ % ของทั้งหมด | ถ้าคลาสไม่สมดุล (เช่น 74/26) — ทายบ่อยสุดทุกแถวก็ได้ 73.6% แล้ว! |
| `Precision` | พูด "yes" แล้วถูกกี่ % | สำคัญเมื่อค่าใช้จ่ายในการผิดพลาดสูง |
| `Recall` | เห็น "yes" จริงแล้วจับได้กี่ % | สำคัญเมื่อพลาดเป้าหมาย = ขาดทุน (เช่นสินเชื่อผิดนัด) |
| `F1` | ค่ากลางของ Precision+Recall | **ตัวเลือกแรกเมื่อคลาสไม่สมดุล** |
| `baseline` | ทายคลาสบ่อยสุดทุกแถวได้กี่ % (ทายโง่ ๆ ไม่ใช้โมเดลเลย) | โมเดลต้องชนะ baseline **ใน metric ที่เราสนใจ** |

**ตัวอย่างการตีความจริงจากข้อมูลชุดนี้:** LDA/MLP ได้ accuracy สูงสุด (0.768) แต่ recall ต่ำ (0.44 และ 0.37) —
คือ "ทาย no เก่ง" / **Logistic ได้ F1 สูงสุด (0.552) เพราะจับคลาส yes ได้จริง (recall 0.71)** — ถ้าเป้าหมายคือจับคนผิดนัด Logistic จึงน่าใช้กว่า

**Feature importance (ท้ายผล):** รายการ feature ที่โมเดลให้ความสำคัญ — ใช้ตรวจว่าโมเดลอ่านข้อมูลถูกเหตุผลไหม
(เช่นถ้า importance ไปอยู่ที่ `app_id` = มี ID หลุดเข้าไป ต้องไปเพิ่มใน `DROP_COLS`)

## 🤖 โมเดล 10 ตัว — ใช้ตัวไหนเมื่อไหร่

| โมเดล (key ใน MODELS) | จุดแข็ง | จุดอ่อน | ใช้เมื่อ |
|---|---|---|---|
| `logistic` | เรียนรู้ไว อธิบายได้ เสถียร | จับความโค้งไม่ได้ | เริ่มต้นเสมอ / ต้องการ recall สูง |
| `knn` | ง่าย ไม่ต้องสมมติเยอะ | ช้าเวลาข้อมูลใหญ่ โดนสเกล | ข้อมูลเล็ก รูปแบบเป็นกลุ่ม ๆ |
| `tree` | อ่านกฎออก | มัก overfit ถ้าไม่จำกัดความลึก | อยากได้กฎ if-else |
| `nb` | เร็วมาก ไม่พังง่าย | สมมติว่า feature อิสระกัน | ข้อมูลเบื้องต้น / baseline ที่ดี |
| `svm` | แม่นบนข้อมูลกลาง ๆ | ช้ากับข้อมูลใหญ่ | ข้อมูลกลาง ๆ ขอบชัด |
| `rf` | แกร่งทั่วไป ไม่ชอบ overfit มาก | ใหญ่ | ใช้ได้เกือบทุกงาน |
| `gb` | แกร่ง | ช้ากว่า RF นิดหน่อย | ต้องการความแม่น |
| `ada` | ปรับ bias ได้ | ไวต่อ outlier | ข้อมูลค่อนข้างสะอาด |
| `mlp` | จับ pattern ซับซ้อน | ต้องการข้อมูลเยอะ ปรับแพง | ข้อมูลใหญ่ มีความสัมพันธ์ซับซ้อน |
| `lda` | เร็ว เสถียร | สมมติเส้นตรง | เหมาะกับข้อมูลเชิงสถิติ |

## 🧪 วิธีเรียกใช้โมเดลตัวเดียวด้วยตัวเอง

import pandas as pd

## 🧹 โปรแกรมทำความสะอาดอะไรให้อัตโนมัติ

| ข้อมูลสกปรก | จัดการว่า |
|---|---|
| แถวซ้ำทั้งแถว | ตัดออก (กัน train/test contamination) |
| NaN / inf | ตัดแถว |
| ตัวเลขเก็บเป็นข้อความ `"45,000"` | แปลงเป็นตัวเลข (สำเร็จ ≥90% ของคอลัมน์) |
| ข้อความ marker `na / null / - / ?` | ถือเป็น missing |
| คอลัมน์ข้อความ ≤15 หมวด | one-hot 0/1 |
| คอลัมน์ ID / วันที่ / ข้อความเกิน 15 หมวด | ข้ามอัตโนมัติ (+ คอลัมน์ที่ใส่ใน `DROP_COLS`) |
| คอลัมน์ค่าคงที่ | ตัดออก |
| outlier (IQR) | ตัดถ้ารวมกันไม่เกิน 15% ของข้อมูล |
| target เป็นข้อความ ("yes"/"no") | แปลงเป็น 0/1 ให้ (เรียงตามค่า เพื่อให้รันซ้ำได้ผลเดิม) |

> ทุกโมเดลใช้ **split แบบ stratified ด้วย seed 42 เดียวกัน** และ hyperparameter จะถูกเลือกด้วย 5-fold CV **บน train เท่านั้น** (test ไม่ถูกใช้ตอนเลือก = กัน data leakage)
